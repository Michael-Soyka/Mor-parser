# mor-parsers

**Русский** | [English](README.en.md)

Парсеры игровых данных "Мор. Утопия" (Pathologic, Pathologic Classic HD).

Здесь представлены только специфичные для игры форматы. Стандартные, которые игра тоже использует (XML, PNG, OGG Vorbis),
оставлены потребителю и готовым крейтам. Каждый крейт описывает двоичную раскладку своего формата в начале
`lib.rs` или файла модуля.

## Крейты

| Крейт      | Форматы                         | Что даёт                                                                   |
|------------|---------------------------------|----------------------------------------------------------------------------|
| `morvfs`   | `.vfs`                          | Чтение и запись архивов, пакетное чтение через один дескриптор             |
| `mortex`   | `.tex`                          | DDS-текстуры: DXT1/3/5, BGR(A), кубические карты; декодирование в RGBA или исходные mip-уровни |
| `morft`    | `.ft`                           | Растровые шрифты: глифы, метрики, кернинг                                  |
| `mormesh`  | `.mesh`                         | Геометрия всех раскладок, декодер карт освещения, опциональный экспорт в glTF |
| `morscene` | `.isc`, `.osc`, `.pfd`, `.map`  | Сцены, акторы, данные поиска пути, карта города, опциональный экспорт в glTF |

### morvfs

Архивы `LP1C`: дерево каталогов с именами в cp1251 и метками времени FILETIME, за ним данные файлов.
`Vfs::open` читает дерево, `Vfs::reader` держит один дескриптор файла на много чтений,
`extract_all` / `extract_matching` распаковывают на диск, `VfsWriter` собирает новый архив.

### mortex

Файл `.tex` - обычный DDS. `Texture::decode( face, mip )` возвращает RGBA8,
`Texture::level( face, mip )` - хранимые байты для загрузки сжатой текстурой.

### morft

Растровые шрифты `.ft`: высота строки и ячейки, положение и сдвиг каждого глифа, кернинговые пары,
8-битные битовые карты покрытия.

### mormesh

`Mesh::parse` выбирает раскладку по ведущему нулю и по тому, какая раскладка прочитывает файл ровно до конца:

- `Static`: поверхности с картами освещения, оболочки столкновений;
- `Movable`: поверхности без карт освещения и OBB;
- `Land`: ландшафт, тайлы поверхностей;
- `Raw`: одна текстурированная поверхность;
- `Water`: меши рек и прудов.

Раскладки, которые движок выбирает по контексту, разбираются отдельными модулями:

- `layout::interior`: интерьеры, BSP-дерево комнат со столкновениями и поверхностями с картами освещения;
- `layout::detail`: растительность, экземпляры raw-мешей по сетке, поворот воспроизводится через ГСЧ движка;
- `layout::character`: персонажи со скиннингом, скелетом, присоединёнными объектами и анимациями.

`lightmap` декодирует страницы карт освещения: вариант JPEG-LS (LOCO-I) с NEAR = 2, четыре mip-уровня L8,
перенесён из `D3D.dll` и побитово сверен с исходным кодом.

Опция `gltf` добавляет экспорт в `.glb` или `.gltf` + `.bin`.

### morscene

`Scene::load` читает интерьер `.isc` или уличную сцену `.osc` так же, как игра (нестрогий XML,
включения `<reference>` разрешаются через callback). Остальные модули:

- `actor`: двоичные описания акторов из `Actors.vfs`: геометрия сцены, источники и группы света
  с коронами, вода, растительность;
- `path`: навигационная сетка `.pfd`, граф рёбер и сетка поиска;
- `map`: `city.map`, контуры районов и изображение внутриигровой карты с указываемыми областями.

Опция `gltf` экспортирует загруженную сцену: ландшафт или интерьер, каждый актор с мешем,
источники света как точечные `KHR_lights_punctual` и точки сцены как пустые узлы.

## Не поддерживается

- лицевая анимация LifeStudio:Head: меши голов `.lsh`, последовательности липсинка `.mms`, библиотеки анимаций `.mma`;
- шейдеры;
- экспорт
  - скелеты и анимации персонажей в glTF, персонажи выгружаются в исходной позе;
  - карты освещения в экспорте glTF;
- данные столкновений у акторов геометрии;
- несколько акторов света, чья раскладка не совпадает с остальными.

## Примеры использования

Утилиты командной строки в `crates/*/examples`:

```sh
cargo run -p morvfs  --example extract    -- <archive.vfs> [out_dir]
cargo run -p mortex  --example tex2png    -- <Textures.vfs> <name.tex> <out.png> [mip]
cargo run -p morft   --example text2png   -- <Fonts.vfs> <name.ft> <text> <out.png>
cargo run -p mormesh --example mesh2obj   -- <Geometries.vfs> <name.mesh> <out.obj>
cargo run -p mormesh --example mesh2gltf  --features gltf -- <data_dir> <name.mesh> <out.glb | out.gltf>
cargo run -p morscene --example scene2gltf --features gltf -- <data_dir> <name.isc | name.osc> <out.glb | out.gltf>
```

`data_dir` - папка `data` игры с архивами `.vfs`; текстуры встраиваются как PNG.

## Координаты

В игре левосторонний Direct3D с лицевыми гранями по часовой стрелке, Y вверх. Парсеры возвращают данные
как есть; экспорт в glTF инвертирует z и разворачивает порядок обхода.

## Пример кода

```toml
[dependencies]
morvfs   = { git = "https://github.com/Michael-Soyka/mor-parsers" }
mortex   = { git = "https://github.com/Michael-Soyka/mor-parsers" }
mormesh  = { git = "https://github.com/Michael-Soyka/mor-parsers", features = [ "gltf" ] }
```

```rust
use mormesh::Mesh;
use mortex::Texture;
use morvfs::Vfs;

let textures = Vfs::open( "data/Textures.vfs" )?;
let image = Texture::parse( &textures.read( "wall.tex" )? )?.decode( 0, 0 )?;

let geometries = Vfs::open( "data/Geometries.vfs" )?;
let mesh = Mesh::parse( &geometries.read( "bench.mesh" )? )?;
```

## Тесты

```sh
cargo test --workspace --all-features
```

Модульные тесты работают на синтетических данных.

Тесты в `crates/*/tests` идут по установленной игре,
путь к которой задаёт `PATHOLOGIC_DATA` (значение по умолчанию в `.cargo/config.toml`, переопределяется.
из оболочки); если папки нет, они пропускаются.
